## 1. 要解决的问题

在 Tine（Logseq 同构）笔记里，一个块可以用 `((uuid))` 引用另一个块。这种写法对人（Tine 会渲染）没问题，但 **AI 在 VS Code 里读 `.md` 原文时只能看到一串 UUID，看不到被引块的真实内容**，于是无法正确理解和整理笔记。

本插件要做的事：**把「UUID → 块子树真实内容」的解析能力交给 AI**，同时顺带解决人看笔记时的悬停预览问题。

## 2. 已用真实环境验证的事实（不是推测）

写计划前我先做了实测，以下结论都来自你这台机器和你的真实笔记库。

### 2.1 笔记格式

抽样文件 `pages\2驱动方分类、剧情模式.md`：

```
- # 2 导演一人身兼两角
  collapsed:: true
  id:: 678bcfae-dea4-4cee-8c7f-ea71ff0b3c0b
	- 即驱动人物有双重身份……
			- 1、如果主角决定对抗导演……参见 ((66c73a56-ddda-44d2-80dd-009e44406fd4))
```

结论：与 Logseq **完全同构**。

- 块 = `- ` 开头的列表行 + 所有缩进更深的续行
- 块 ID = 续行里的 `id:: <uuid>`
- 块引用 = `((<uuid>))`，可跨文件
- 其他语法：`[[页面]]`、`==高亮==`、`[[$red]]`、`collapsed:: true`

## 4. 核心算法规范

这一节是实现的契约，直接决定正确性。

### 4.1 行分类（判定顺序很重要）

| 类别 | 规则 |
|---|---|
| frontmatter | 首行 `---` 起，到下一个 `---` 或 `...` 结束 |
| 页面属性 | 文件开头连续出现的 `非列表行 + ::`（如 `title::`、`tags::`） |
| 水平线 | `^[ \t]*(?:-[ \t]*){3,}$` —— 必须优先排除，否则 `---` 会被当成空块 |
| 列表行 | `^([ \t]*)-(?:[ \t]+(.*)\|[ \t]*)$` |
| 围栏开 | 根级 fences（缩进 ≤3）或列表项内 fences（`- ```lang`） |
| 围栏闭 | 同类字符、长度 ≥ 开围栏、缩进满足约束 |
| 块 ID | `^\s*id::\s*(<uuid>)`，且缩进 > 所在块的缩进 |
| 其他属性 | `^\s*[^-\s].*?::\s*.*$`，且缩进 > 所在块的缩进 |
| 续行 | 缩进 > 当前块缩进的一切行（含空行） |

**缩进列宽**：制表符按 `tabSize = 4` 对齐到下一个制表位，而不是算 1 列。这一点如果做错，Tab 和空格混用的笔记会解析错位。

### 4.2 块树构建

用「父栈」扫描：

1. 遇到列表行，算缩进 `indent`
2. 弹栈，直到栈顶块缩进 `< indent`
3. 栈顶即父块，当前行开新块并压栈
4. 遇到续行，追加到**当前栈顶块**的内容；同时（按 obsidian 插件的做法）也追加到所有祖先的「子块原文」

块的起止行：首行 ~ 最后一个属于它的续行/子块行。

### 4.3 ID 归属

`id::` 属于「当前打开的块」——也就是缩进恰好比它小的最近的那个列表行。由于它在 4.1 里已要求 `缩进 > 块缩进`，直接记到栈顶块即可。

**同一块可以有多个 `id::` 吗**？你的库里没发现。策略：取第一个，其余忽略并记日志。

### 4.4 引用扫描

- 主正则：`/\(\(([A-Za-z0-9_-]{36,})\)\)/g`
- 一并覆盖 `{{embed ((uuid))}}`（正则自然命中内部）
- 全角 `（（uuid））`：实测 0 例，但支持成本低，一并支持
- **跳过**：frontmatter、围栏内、行内代码（反引号数量要严格配对）
- ID 统一小写归一

### 4.5 索引

- 输入：graph 根下的 `pages/**/*.md` 与 `journals/**/*.md`
- 排除：`logseq/**`、`.tine-trash/**`、`.recycle/**`、`bak/**`、`.git/**`、`node_modules/**`
- 索引结构：
  - `Map<uuid, BlockRef[]>` —— 数组以承载重复 ID
  - `Map<filePath, ParsedFile>` —— 文件级解析结果，供增量更新
- **首次**：全量 0.69 秒，直接同步建完再回应用，不需要持久化缓存
- **之后**：`FileSystemWatcher` 监听 `**/*.md`，只重解析变更文件
- 索引失效：graph 根变化、配置变化、手动「重建索引」命令

### 4.6 渲染（给 AI 看的格式）

对每个请求的块输出：

```markdown
### 块 `66c73a56-ddda-44d2-80dd-009e44406fd4`
来源：`pages/多驱动方的第三方分类、剧情模式.md:131`
子树：38 行 / 1240 字符

## 3.1 棋子觉醒/背叛
这种棋子也可以看作是一种变形者。
在觉醒/背叛之前，棋子本身是驱动方，但其背后还有一个幕后黑手。
  ...
  # 子块层级原样保留
```

渲染规则：

1. 块首行去掉 `- ` 标记，作为标题行
2. **移除** `id::` 与 `collapsed::`（纯元数据 / UI 状态）
3. **保留**其他属性（如 `tine.author::`，可能有语义）
4. 子块保留列表标记与**相对缩进**（tab → 2 空格规范化），让 AI 看出层级
5. 结尾标注来源路径与行号，方便 AI 继续深挖

### 4.7 嵌套引用的递归展开

块 A 的子树里还有 `((B))`。若只输出原文，AI 仍然看不懂 B。

策略：

- 递归展开，**默认深度 3**（可配置 0 = 不展开）
- 每进入一层加标注：`↳ 引用 ((B)) 展开：`
- **循环检测**：用当前展开路径（栈）判断，命中则输出 `（循环引用，已跳过）`
- **总字符预算**：默认 20 000 字符，超预算时截断并明确告知 `（已截断，剩余 N 处引用未展开）`
- 同一 UUID 在一次调用内重复出现时，第二次起只给摘要与「见上文」

### 4.8 图谱根自动识别

从工作区文件夹出发，自身或上级目录满足下述任一条件即认定：

- 同时存在 `pages/` 和 `logseq/`
- 存在 `logseq/config.edn`
- 存在 `.tine-trash/`

识别不到时提示用户在设置里手动指定，并给出一键选择目录的命令。

## 5. 对外能力

### 5.1 Language Model Tools（AI 主路径）

三个工具，全部 `canBeReferencedInPrompt: true`，用户可 `#` 手动指定。

#### ① `tineBlockRef_readBlock` — 按 UUID 读块

```
输入：
  blockIds: string[]         必填，1~20 个 UUID
  includeChildren?: boolean  默认 true（用户已确认要含子块）
  compact?: boolean          默认 false；true 时只输出块首行文本
  maxDepth?: number          默认 3；嵌套引用展开深度
输出：
  每个块的来源、内容、子树规模、异常标注
```

这是最核心的工具。`modelDescription` 会明确写：
> 当笔记里出现 `((uuid))` 形式的块引用、需要知道它指向的真实内容时调用本工具。

#### ② `tineBlockRef_readNote` — 按文件批量解析

```
输入：
  filePath: string           必填，绝对路径
  mode: "expand" | "list" | "both"   默认 expand
  includeChildren?: boolean  默认 true
  maxDepth?: number          默认 2
输出：
  expand → 把文件里所有 ((uuid)) 就地替换成展开内容后的完整 Markdown
  list   → 只列「行号 → UUID → 摘要」
  both   → 两者都要
```

**这个工具是「AI 读笔记」场景的关键**：AI 读完 `.md` 后只需再调一次，就能拿到带上下文的完整版本。

#### ③ `tineBlockRef_findBacklinks` — 反向链接

```
输入：blockId: string
输出：引用该块的所有位置（文件、行号、引用所在块的上下文首行）
```

对应用户勾选的「Tine `refs --block` 等价物」。

### 5.2 命令（不依赖 AI 主动性的兜底入口）

| 命令 | 行为 |
|---|---|
| `块引用：展开当前笔记为 AI 可读版` | 把当前 `.md` 的全部引用就地展开，输出到**新标签页**（可另存） |
| `块引用：展开光标处的块引用` | 光标在 `((uuid))` 上时，展开结果输出到新标签页 |
| `块引用：查看块的反向链接` | 树视图 / 输出面板列出引用位置，可点击跳转 |
| `块引用：重建索引` | 手动全量重建，显示耗时与统计 |

第 1 条是**最重要的兜底**：即使模型不愿意调工具，你也能一键得到一份 AI 完全读得懂的笔记文本，然后在 Chat 里 `#file` 引用它。

### 5.3 悬停预览

- `vscode.languages.registerHoverProvider({ language: 'markdown' })`
- 只在 graph 内的 `pages/`、`journals/` 文件生效
- 悬停 `((uuid))` 显示：块内容（默认前 6 行）+ 来源 + 「展开全文」链接
- 悬空引用显示明确的「目标块不存在」
- 重复 ID 显示「存在 N 个同名 ID 的块」并列出候选

## 7. 异常与边界处理

| 情况 | 处理 |
|---|---|
| 悬空引用（19 个） | 明确返回「目标块不存在，可能已被删除」，**不静默失败**——这对 AI 是有用信息 |
| 重复 ID（8 个） | 返回全部候选，标注「该 UUID 在 N 处重复定义」，并给出各自来源 |
| 展开体积超预算 | 截断 + 明确告知截断了什么、剩余多少 |
| 循环引用 | 路径栈检测，输出「循环引用，已跳过」 |
| 非 graph 文件被调用 | 提示该文件不在索引范围 |
| 文件编码非 UTF-8 | 以 UTF-8 读取并容错替换；不写回，不会破坏原文件 |
| 中文路径 | 全链路 `Uri.fsPath`，不做 URL 编码转换 |

> **本插件全程只读**：不修改、不格式化、不重写任何笔记文件。所有输出都走新标签页 / 工具返回值 / 悬停。
