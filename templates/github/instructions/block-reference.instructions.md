# 本笔记库的 AI 协作约定

## 一、块引用必须展开后再理解

本笔记库使用 Tine（与 Logseq 同构）格式。`((uuid))` 是**块引用**，`{{embed ((uuid))}}` 是**嵌入引用**。两者都只是一串 ID，**本身不含任何语义**。

**硬性规则**：

1. 读到 `((uuid))` 或 `{{embed ((uuid))}}`，**必须调用 `blockRef`** 获取目标块真实内容。不要猜测，不要跳过，不要仅凭上下文脑补。
2. 要理解一整篇笔记时，**优先调用 `blockNote`**，而不是普通文件读取——普通读取只能看到 UUID。
3. 想知道某条结论被谁引用，调用 `blockBacklinks`。
4. 工具返回「未找到」时，**如实告诉用户**该引用无法解析，不要编造内容。
## 二、三个工具怎么用

| 工具 | `#` 引用名 | 何时用 |
|---|---|---|
| 按 UUID 读块 | `#blockRef` | 已知 UUID，要看它指向的块 + 全部子块 |
| 读整篇笔记 | `#blockNote` | 要理解一篇笔记的全貌 |
| 查反向链接 | `#blockBacklinks` | 想知道谁引用了这个块 |

### blockNote 的模式选择（决定能不能读到内容）

- 不确定这篇笔记有多少引用 → **先用 `mode: "list"`**。它只返回清单（行号 + UUID + 目标块首行），通常几 KB，绝不会被截断。
- 确认引用不多、或需要完整上下文 → 用 `mode: "expand"`（默认）。
- 若返回里出现「**以下 N 处块引用未展开**」，说明超了输出预算，**用 `blockRef` 逐个读取那些 UUID**。

### blockBacklinks 的输出结构

按**页面分组**，每个页面下按行号列出引用位置：

```
## 傲娇
`pages/傲娇.md` · 1 处引用

- 71 举例 › 71.3 毒舌讽刺型        ← 引用所在块的祖先路径
  - 第 145 行 · 行内引用
```

`›` 分隔的是块在笔记里的层级位置。**这个路径本身就是重要信息**——同样是「引用了这个块」，出现在「71.3 毒舌讽刺型」下面和出现在「2.1 平时」下面，含义完全不同。回答「谁引用了它」时要把路径带上，不要只报文件名。

### 反面教材

对引用很多的笔记一次性调 `expand`，拿到被截断的半截内容后改用 grep / view 读源文件——那样只能看到 UUID，等于完全没读。正确做法是 `mode:list` → 挑需要的 `blockRef`。

## 三、笔记结构说明

- `pages/` 与 `journals/` 下是真实笔记，参与索引。
- `logseq/` 是 Tine 的元数据与回收站（`.recycle`、`.tine-trash`、`bak`），**不是笔记内容**，不要当作资料引用。
- 块 ID 写在 `id:: <uuid>` 行里；块引用写作 `((<uuid>))`；嵌入引用写作 `{{embed ((<uuid>))}}`。
- `collapsed::` 只是 UI 折叠状态，`id::` 是块标识，两者都不携带语义。
- `[[页面名]]` 是页面链接，`[[$red]]==文字==` 是 Tine 的高亮/着色语法，都不是块引用。

## 四、整理笔记时的注意事项

- 修改笔记前先确认用户意图；本笔记库由 Tine 编辑，直接改文件可能造成同步冲突。
- 引用内容可能很长（个别块超过 400 行），必要时用 `compact` 参数只要首行，或分批读取。
- 同一个 UUID 可能在多个文件重复定义（复制粘贴造成），工具会列出全部候选，报告时要说清楚是哪一处。
