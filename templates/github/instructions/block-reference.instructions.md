# 本笔记库的 AI 协作约定

## 一、块引用必须展开后再理解

本笔记库使用 Tine（与 Logseq 同构）格式。`((uuid))` 是**块引用**，`{{embed ((uuid))}}` 是**嵌入引用**。两者都只是一串 ID，**本身不含任何语义**。

**硬性规则**：

1. 读到 `((uuid))` 或 `{{embed ((uuid))}}`，**必须调用 `#blockRef`** 获取目标块真实内容。不要猜测，不要跳过，不要仅凭上下文脑补。
2. 要理解一整篇笔记时，**优先调用 `#blockNote`**，而不是普通文件读取——普通读取只能看到 UUID。
3. 想知道某条结论被谁引用，调用 `#blockBacklinks`。
4. 工具返回「未找到」时，**如实告诉用户**该引用无法解析，不要编造内容。
## 二、读笔记与写笔记的工具

| 工具 | `#` 引用名 | 何时用 |
|---|---|---|
| 按 UUID 读块 | `#blockRef` | 已知 UUID，要看它指向的块 + 全部子块 |
| 读整篇笔记 | `#blockNote` | 要理解一篇笔记的全貌 |
| 查反向链接 | `#blockBacklinks` | 想知道谁引用了这个块 |
| 生成新 ID | `#blockNewId` | 新建块且这个块需要被别处引用 |
| 查找块 | `#blockFind` | 按标题/内容找已有块，拿 UUID 或行号；也可列举整篇笔记的大纲 |
| 一次链接多个块 | `#blockLink` | **引用已有块的默认选择**，一次调用算完补 ID + 写引用 |
| 准备引用补丁 | `#blockMakeRef` | 只需引用单个块、且只想补 ID 时 |
| 校验 | `#blockCheck` | 写完 `id::` 或 `((uuid))` 后检查 |

### 列举笔记结构（找「第 N 个标题」的正确做法）

要引用「某篇笔记的第 2 个二级标题」这类位置，**不要用终端扫文件**。一次调用：

```text
#blockFind { filePath: "pages/傲娇.md", headingsOnly: true, headingLevel: 2, limit: 200 }
```

返回按文件顺序编号的单行清单，一级到四级标题都能查：

```text
1. pages/傲娇.md:5    # 11 行为模式概括   no id
2. pages/傲娇.md:53   # 12 收到情感表达   id: 68010957-…
```

`headingLevel` 省略时返回所有层级；`query` 留空表示不按关键词过滤（必须同时给 `filePath`）。

### blockNote 的模式选择（决定能不能读到内容）

- 不确定这篇笔记有多少引用 → **先用 `mode: "list"`**。它只返回清单（行号 + UUID + 目标块首行），通常几 KB，绝不会被截断。
- 确认引用不多、或需要完整上下文 → 用 `mode: "expand"`（默认）。
- 若返回里出现「**以下 N 处块引用未展开**」，说明超了输出预算，**用 `blockRef` 逐个读取那些 UUID**。

### blockBacklinks 的输出结构

按**页面分组**，每个页面下按行号列出引用位置：

```
## 傲娇
`pages/傲娇.md` · 1 处引用

- 71 举例 › 71.3 毒舌讽刺型        ← 引用所在块的祖先路径
  - 第 145 行 · 行内引用
```

`›` 分隔的是块在笔记里的层级位置。**这个路径本身就是重要信息**——同样是「引用了这个块」，出现在「71.3 毒舌讽刺型」下面和出现在「2.1 平时」下面，含义完全不同。回答「谁引用了它」时要把路径带上，不要只报文件名。

### 反面教材

对引用很多的笔记一次性调 `expand`，拿到被截断的半截内容后改用 grep / view 读源文件——那样只能看到 UUID，等于完全没读。正确做法是 `mode:list` → 挑需要的 `blockRef`。

## 三、笔记结构说明

- `pages/` 与 `journals/` 下是真实笔记，参与索引。
- `logseq/` 是 Tine 的元数据与回收站（`.recycle`、`.tine-trash`、`bak`），**不是笔记内容**，不要当作资料引用。
- 块 ID 写在 `id:: <uuid>` 行里；块引用写作 `((<uuid>))`；嵌入引用写作 `{{embed ((<uuid>))}}`。
- `collapsed::` 只是 UI 折叠状态，`id::` 是块标识，两者都不携带语义。
- `[[页面名]]` 是页面链接，`[[$red]]==文字==` 是 Tine 的高亮/着色语法，都不是块引用。
- **一个块可以跨多行**：块首行（`- ` 开头）之后的缩进续行仍属于同一个块；只有再次出现 `- ` 才是子块。代码围栏内的所有行也属于外层块。

## 四、整理笔记时的注意事项

- 修改笔记前先确认用户意图；本笔记库由 Tine 编辑，直接改文件可能造成同步冲突。
- 引用内容可能很长（个别块超过 400 行），必要时用 `compact` 参数只要首行，或分批读取。
- 同一个 UUID 可能在多个文件重复定义（复制粘贴造成），工具会列出全部候选，报告时要说清楚是哪一处。

## 五、写笔记时如何生成块引用

### 1. 新建一个之后会被引用的块

先调用 `#blockNewId`，不要自己编造 UUID。把返回的 `id::` 行放在块首行正下方：

```markdown
- 新块标题
  id:: <#blockNewId 返回的 UUID>
  正文
```

规则：

- `id::` 必须紧接块首行，比块项目符号多两个空格缩进；Tab 保持 Tab；
- `id::` 必须在正文和子块之前；写在正文之后 Logseq 不会识别；
- 如果新块首行本身是代码围栏（例如 `- ```js`），把 `id::` 放在闭合围栏之后、子块之前；Tine 能读，但 Logseq 可能不识别，要在回复里提醒用户；
- 不要给所有块批量加 `id::`，只给真正需要被引用的块加。

### 2. 引用一个已有块

**默认用 `#blockLink`，一条调用搞定。** 先定位目标，再一次性拿到全部补丁：

```text
#blockFind  { filePath: "pages/傲娇.md", headingsOnly: true, headingLevel: 1 }
#blockLink  {
  destination: { filePath: "pages/我的笔记.md", line: 6, expectedFirstLine: "引用区" },
  targets: [
    { filePath: "pages/傲娇.md", line: 5,   expectedFirstLine: "# 11 行为模式概括", label: "行为模式" },
    { filePath: "pages/傲娇.md", line: 387, expectedFirstLine: "# 13 产生情感需求", label: "情感需求", kind: "embed" }
  ]
}
```

`#blockLink` 会：给没有 `id::` 的目标生成 UUID 并给出补丁、算好落点的缩进与层级、
保证引用前面的空格，一次返回所有补丁。你只需要用编辑工具原样应用，然后 **调用一次** `#blockCheck`。

补丁应用规则：

1. 用你自己的文件编辑工具，把每个 `oldText` 原样替换成 `newText`；
2. 不要顺手改其他内容，不要调整缩进、顺序或合并补丁；
3. 同一个文件有多处补丁时，可以在一次编辑里全部应用。

只有在「只想引用单个块、且不需要写入落点」时，才退回 `#blockMakeRef`：

- 候选已有 UUID → 直接写 `((uuid))`；
- 候选没有 `id::` → 用候选的文件与行号调用 `#blockMakeRef`；
- 候选的 ID 标为「非法」→ 先告诉用户该 ID 不是标准 UUID，不要直接引用。

### 3. 写完必须校验

写完 `id::` 与引用后调用 `#blockCheck`：

- 有 **错误**（悬空引用、重复 UUID、`id::` 在正文后、畸形 `((...))`）→ 先修，再继续；
- 有 **警告**（v8 运行时 ID、零缩进、代码围栏后的 `id::`、**引用前缺空格**）→ 在回复里告诉用户，不要静默忽略；
- 不要把 `((uuid))` 放进代码围栏或行内代码，否则会被当成示例而不是引用。

### 4. 引用语法

- 行内引用：`((uuid))`
- 嵌入引用：`{{embed ((uuid))}}`
- 不要写 `(((uuid)))`：Logseq 会解析失败。
- **`((` 和 `{{embed` 前面必须是行首或空白字符**。这是 Tine / Logseq 的原生规则：只有「行首」或
  「空白之后」的引用才会被识别；紧贴文字、中文标点、括号的都会被当成普通文本，在 Tine 里根本不显示成引用。
  本扩展能扫到这种写法（所以 VS Code 里看着正常），这是最容易漏掉的一类坏引用。

  同一行前面已经有内容时，**必须补一个空格**（`{{embed ...}}` 的 `{{` 同样适用）：

  ```markdown
  - 参考 ((uuid))                        ✅ 前面是空格
  - 参考： ((uuid))                       ✅ 前面是空格（中文标点后再加一个半角空格）
  - 参考：((uuid))                        ❌ 紧贴全角冒号，Tine 不认
  - ((uuid))                             ✅ 行首
  - 参考 {{embed ((uuid))}}               ✅ 前面是空格
  - 参考：{{embed ((uuid))}}               ❌ 紧贴全角冒号，Tine 不认
  ```

  追加引用时不要图省事直接接在句尾，先看看前一个字符是不是空白。

### 5. 大纲格式：块内多行 vs 子块

生成内容时必须区分两种「换行」，写错会改变笔记结构。

**同一块内的多行（软换行）**：用缩进续行，**不加 `- `**。

```markdown
- 块标题
  第一段内容
  第二段内容
```

**子块**：加 `- ` 并比父块多缩进一级。

```markdown
- 块标题
	- 子块一
	- 子块二
```

**错误写法**：把本该属于同一块的多行都写成 `- `，会变成多个同级块。

```markdown
- 块标题
- 第一段        ← 错：成了独立块，不再是上一块的内容
- 第二段        ← 错
```

写整段文字、说明、代码示例时，默认用**软换行**留在同一个块里；只有真正的并列条目才拆成子块。

### 6. 用户手动编辑时的按键行为

本插件在 Tine 图谱内接管了编辑键，回答「怎么操作」时按这个说：

- **回车**：拆出同级新块；空块上回车会继续新建空块。
- **Shift+Enter**：块内软换行，不产生新块。
- **代码围栏内**：两种键都只换行，并保留当前行缩进（避免把列表项代码块拆断）。
- 块首行的 `- ` 标记区域内、frontmatter、页面属性、表格中，保持 VS Code 原生行为。

## 六、最短路径：不要自己加验证

每调用一次工具就是一轮完整的模型响应，往返次数直接决定用户的等待时间。
用户实测里最慢的一次，16 次调用中有 8 次是 AI 自己加的「保险」。以下行为一律不要做。

**必须避免**

1. **不要用终端读文件。** 想看内容用编辑器自带的读取工具；`#blockFind` / `#blockLink` 已经给出文件、行号、UUID。
2. **不要用终端 grep 或 powershell 扫笔记找结构。** 找标题用 `#blockFind` + `headingsOnly` + `headingLevel`，一次调用。
3. **`#blockLink` / `#blockMakeRef` 之后不要用 `#blockRef` 回读验证。** `#blockCheck` 一次就能确认 ID 是否生效。
4. **整篇写完只跑一次 `#blockCheck`。** 不要在每次编辑后都跑。
5. **不要先展示补丁再等确认。** 直接应用，用户可以点「不接受」撤销。
6. **不要为了「保险」重复读回文件比对内容。** 只有在工具报错、或补丁匹配失败时才展开诊断。

**标准调用链**

| 任务 | 调用链 |
|---|---|
| 把 1~N 个已有块引用到另一篇笔记 | `#blockFind` → `#blockLink` → 应用补丁 → `#blockCheck` |
| 只查某个块被谁引用 | `#blockBacklinks` |
| 读笔记并展开引用 | `#blockNote` |
| 新建块并让它可被引用 | `#blockNewId` → 写入 → `#blockCheck` |

一次「引用 2 个块」的完整任务，**4 次调用内结束**。超过就说明你在绕路。
